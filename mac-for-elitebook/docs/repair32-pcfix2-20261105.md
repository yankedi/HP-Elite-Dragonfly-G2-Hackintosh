# R32-PCFIX2：清理 Gen8 计算编码器 PIPE_CONTROL / L3ALLOC 全面通关 Geekbench 6.5.0 Metal 全部 8 项工作负载（2026-11-05）

## 1. 根因与变更摘要
在 `R32-ELSQWAIT` 突破 `Horizon Detection` 后，第 4 项工作负载 `Edge Detection` 在单上下文连续成功运行 7 个 batch 后，于第 8 个 batch 的 `ACTHD = 0x4ecfe3a8`、`IPEHR = 0x7a000004`（`PIPE_CONTROL`）、`CSFLFLAG = 0x50000000`、`CSFLTRK = 0x12000001` 处挂起。

通过对 `AppleIntelTGLGraphicsMTLDriver` 的反汇编分析与 `HP-PCFIX` 运行时指令转储确认，macOS Tahoe 的计算命令传输层仍继承自 Gen8（`COCLGen8CommandTransport`），在每个计算编码器（`IGAccelComputeCommandEncoder`）中发射了与 Gen12 Tiger Lake 硬件不兼容的遗留指令：
1. **`COCLGen8CommandTransport::ResetPreambleCmds`**（编码器前导 `dw[0..32]`）：
   - 连续发射两个 `PIPE_CONTROL`（`7a000004 00000480`：`Texture Cache Invalidation Enable | Pipe Control Flush Enable`），**未设置 `CS Stall`（`bit 20 = 0x00100000`）**，违反 Gen12 硬件规范（在 Gen12 上设置 `Texture Cache Invalidation Enable` 必须伴随 `CS Stall`）。
   - 向 Gen12 已不存在的 Gen8 `L3ALLOC` 寄存器 `0x0000b134` 发射 `MI_LOAD_REGISTER_IMM`（`11000001 0000b134 d0000020`）。
2. **`COCLGen8CommandTransport::AddPipeFlushCmd`**（编码器内/末尾同步 `PIPE_CONTROL`）：
   - 发射 `7a000004 001044a0 <m_pScratchPage+0x10> 0 0 0`，在同一个 `PIPE_CONTROL` 中同时开启 `CS Stall`（`0x100000`）、Gen8 遗留的 `Post-Sync Write Immediate`（`0x4000`，向全局共享的 `m_pScratchPage + 0x10` 写入 64 位立即数 `0`）、`Texture Cache Invalidation Enable`（`0x400`）、`Pipe Control Flush Enable`（`0x80`）与 `DC Flush Enable`（`0x20`）。在高频计算派发与跨上下文抢占下，该虚拟 `Post-Sync Write Immediate` 结合顶层/底层混合缓存失效会导致 Gen12 RCS Flush Tracker（`CSFLTRK = 0x12000001`、`CSFLFLAG = 0x50000000`）死锁。
   - **对照实验验证（`trial-r32-pcfix-retry1-20261105`）**：若在编码器中间的 `AddPipeFlushCmd` 中强行注入 `Media State Clear`（`0x00010000`，即将 `0x001044a0` 改写为 `0x00111020`），由于同一计算编码器内连续两个 `GPGPU_WALKER` 之间使用了 `AddPipeFlushCmd` 且不会重新装载 `MEDIA_VFE_STATE`，会在 `Background Blur` 的后续 `GPGPU_WALKER`（`CSCMDOP = 0x7105000d`、`INSTDONE_1 = 0xffdcffff` `Not done = VFE, TSG0, CS`）立即挂死。

### `R32-PCFIX2` 精确修复（`kern_gen11.cpp`，补丁见 [`../patches/nootedgreen-r32-pcfix2-20261105.patch`](../patches/nootedgreen-r32-pcfix2-20261105.patch)）
Hook `IntelMTLComputeFunctions::execute`（文件偏移 `0x6bf20`，即 `IGAccelComputeCommandEncoder::endEncoding` 完成全部指令编码并调用 `processCurrentBatch` 提交前的入口），在 `hpSanitizeComputeEncoder` 中对当前计算编码器的命令缓冲区（`encoder + 0x88` 起止指针 `[cmdBase, cmdCur)`）做就地净化：
- **前导序列修复**：将两个 `0x00000480` `PIPE_CONTROL` 补齐 `CS Stall`（`0x00000480 -> 0x00100480`），并将 `MI_LOAD_REGISTER_IMM 0xb134`（`dw[15..17]`）清零为 `MI_NOOP`，保留原有的 `0x001010a0` 不变。
- **`AddPipeFlushCmd` 修复**：仅清除 `0x001044a0` 中的 `bit 14`（`0x00004000` `Post-Sync Write Immediate`）及对应的 `m_pScratchPage + 0x10` 地址 `dw[2..3]`，将其改写为 `0x001004a0`（`CS Stall | Texture Cache Invalidate | Pipe Control Flush Enable | DC Flush`），**不注入 `Media State Clear`（`0x00010000`）**，从而在消除 `Post-Sync Write Immediate` 死锁的同时完整保留多派发编码器内的 VFE 状态。
