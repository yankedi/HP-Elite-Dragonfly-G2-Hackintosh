# Track C 中文交付说明

规范及精确offset在`FAULTRECORD-V2.md`/`schema.md`，代码在`source/`，实际结果在`results.json`。这些是离线数据模型和codec，没有reader、MMIObackend或运行中的驱动入口。

## 两层结论独立

READ_SAFE含12个拆分条件：准确binary、HookABI、正确GT域、对象寿命、MMIO地址映射、runtimepower、GT引用、same-requestACK、读副作用安全、reset/clear/teardown排他、恢复不受破坏、默认关闭。关键UNKNOWN使其BLOCKED。设备tuple不可信不能代替这一审查，也不能拿“仅保留raw”绕过安全读取门。

FAULT_DATA_COHERENT包含10个维度：同事件tuple、软件epoch、latch、ABA、地址、context/PML4、engine、allocationgeneration、reset/clearphase、完整性。可以在数据记录里保留不可信raw，不能生成有效VA/确定根因。两个状态域和每个字段来源都独立保存，caller声明不自认证。

## 版本与身份

v1保留GA34原header和原decoder的108字节定义；v2使用独立version2，384字节、little-endian、显式padding/保留零字节，不dump宿主struct。presence与unknown互斥，缺失/未知字段canonicalzero，不从页范围/epoch等猜context、PML4、ringhead、engine或allocationgeneration。

v2包括三个独立采样时点、raw三DWORD、分离的derived字段和来源声明。身份与上下文字段optional；boot/hang/caller/epoch等是记录关联claim，不是设备真实性凭据。旧报告关联通过外部显式匹配，不能自动补旧wire缺失字段。

## 审计修复

初版能roundtrip伪造derivedVA、未充分校验数值/MBZ和correlationflag一致性，独立初审在`../track-d/codec-review/AUDIT.md`。修复采用canonicalraw→derived重新计算、范围与结构一致性检查、双向外部关联约束，并比较全部derived字段。DATA1MBZ可作为不可信raw保留，但禁止派生有效VA。codec不能验证观察者truth，新的严格检查只防内部不一致。

初版结果/logs/样本保存在`audit-before-fix/initial-checkpoint/`，修复后独立关闭报告在`../track-d/codec-review/FINAL-CLOSURE.md`。当前矩阵8profiles、codec140断言、gates71断言；这些是合成/CPU验证，不是GPU验证。修复后样本SHA为`ca2e1f32a0de781728c725ab5a5cc1087e9a55cb3947f8090b03f33198c250f0`。
